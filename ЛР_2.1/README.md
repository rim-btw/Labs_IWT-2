# Лабораторная работа: Разработка набора тестов для функции add

## 1. Какие группы ситуаций выбраны?
Для тестирования функции `add(nums, target)` были выбраны следующие группы ситуаций:
1. **Базовый случай (Happy Path):** Поиск пары в середине и в конце списка.
2. **Работа с отрицательными числами и нулём:** Проверка корректности математических операций при наличии отрицательных значений.
3. **Дубликаты в списке:** Проверка того, что функция возвращает индексы *разных* элементов, даже если их значения совпадают.
4. **Отрицательная целевая сумма (target):** Проверка работы функции при поиске отрицательной суммы.
5. **Крайние случаи (Edge Cases):** Пустой список, список из одного элемента.
6. **Отсутствие решения:** Ситуация, когда подходящей пары в списке нет.

## 2. Какие потенциальные ошибки способен обнаружить каждый тест?
-   `test_basic_case`: Ловит ошибки в базовой логике поиска.
-   `test_pair_at_the_end`: Ловит ошибки, связанные с преждевременным завершением цикла (когда алгоритм не доходит до конца списка).
-   `test_negative_numbers`: Ловит ошибки при работе с отрицательными числами.
-   `test_duplicate_numbers`: Ловит ошибку, когда функция возвращает один и тот же индекс дважды (например, `[1, 1]`), что нарушает условие «индексы двух разных элементов».
-   `test_negative_target`: Проверяет корректность вычисления разности при отрицательном target.
-   `test_no_solution` и `test_empty_list`: Ловят ошибки обработки исключений. Если разработчик забыл обработать случай отсутствия пары, тест упадёт с ошибкой вместо возврата `None`.
-   `test_single_element`: Проверяет, что функция не пытается найти пару внутри одного элемента.
-   `test_zeros`: Ловит ошибки, связанные со значением `0` (например, если в коде есть проверка `if num:` вместо `if num is not None:`).

## 3. Почему набор достаточно разнообразный?
Набор считается разнообразным, так как он покрывает не только «идеальные» сценарии, но и граничные условия (пустые массивы, один элемент, отсутствие решения). Мы проверили как положительные, так и отрицательные числа, а также дубликаты. Каждый тест проверяет уникальное свойство функции или конкретный крайний случай, что позволяет выявить большинство логических ошибок в реализации.
